# GhostEcos — правила для агента

**Обязательно перед любой задачей:** прочитать `AGENTS.md`, `PROFILE.md`, `STYLE.md` (все три в корне рабочей копии, загружаются как инструкции).

**Проект:** GhostEcos — privacy-first экосистема (E2E-мессенджер GhostChat, соцсеть GhostSocial, внутренняя экономика GhostBank), соло-разработка владельца. Демо: https://ghostecos.duckdns.org.
Серверный стек: Python 3.12 / FastAPI / uvicorn / SQLite (WAL) / nginx. Фронт легаси: vanilla JS + PWA, фреймворки разрешены. Мобильная часть: Android APK / Flutter (ghostchat_mobile_lib, desktop_wrapper, GhostEcosOTA).

## Стиль ответов
- Всегда русский язык: ответы, комментарии в коде, сообщения коммитов.
- При выполнении задач — минимум текста и действий. В переписке — обычно. Если просят развёрнуто — максимально развёрнуто.
- Без воды, извинений, вводных-заполнителей и «насыщенных» ответов.
- Экономь бюджет лимита: минимум лишних действий, повторов и чтений без необходимости.
- Если знаешь способ лучше — ВСЕГДА предлагай. Свои идеи — по возможности.
- Работа «с нуля» со свободой реализации: сначала обсуждение (вопросы/предложения), потом работа.
- Не выдумывай факты, пути, команды и ответы за пользователя. Не хватает данных — спроси, а не додумывай.

## Технические ограничения
- Бэкенд: FastAPI + uvicorn + SQLite (WAL) — не менять, расширять только в этом стеке.
- Основная рабочая копия: `C:\Users\Home\GE`. Папки `GE_server_latest_*` могут быть устаревшими.
- Источник правды — и сервер, и GitHub: сверяться с обоими перед значимыми изменениями.
- GitHub: `origin` → wakionecontact-source/ghostecos, `ghostchat` → wakionecontact-source/ghostchat, `backup` → wakionecontact-source/ghostchat-lib-backup.

## Сервер и деплой
- Подключение: `ssh ghostecos` (root@ghostecos.duckdns.org, ключ `~/.ssh/ghostecos_ed25519`), код в `/opt/ghostchat/`.
- Агент сам выгружает файлы и перезапускает сервисы — без спроса.
- Перед каждой выгрузкой, заменяющей существующий код, — бэкап старого файла (соглашение сервера: `имя.bak.<дата>`).
- После перезапуска — убедиться, что сервис запустился штатно и ошибок нет, по возможности быстрый тест.
- Разрешено всё, кроме деструктива. Деструктив (удаление, очистка БД, массовая перезапись) — только после подтверждения пользователя и с бэкапами.
- Не трогать без явного указания: `ghostchat.db` (живая БД), конфиги nginx, `.env` / секреты / токены.

## Гит
- Коммитить и пушить можно свободно и часто, ветку выбирать самому.
- Коммиты по-русски. Существующую историю коммитов не переписывать.

## Стиль кода
Стандарт: `STYLE.md` в корне репозиториев (`ghost-workspace`, `GE`). Кратко: комментарии/docstring только по-русски, коротко, объясняют «почему»; без КАПСА, кроме `ВАЖНО:`/`SECURITY:`/`TODO:`; разделители секций `── Название ──`. Python: PEP 8, строка до 100 (+10 макс). JS/Dart: 2 пробела, Dart — `dart format`. Нетронутые участки не переформатируются; стандарт применяется к затронутому и новому коду.

## Тестирование
- Мелкие изменения — smoke-тест (сервис запустился, эндпоинт отвечает).
- Большие/рискованные изменения — полноценные тесты.

## Приоритеты проекта
- Анонимность, приватность и безопасность пользователя — по его выбору.
- Пользователь главный и управляет своими данными.
