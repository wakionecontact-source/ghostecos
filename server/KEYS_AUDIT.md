# Аудит мест где могут сломаться E2E-ключи в GhostChat v1

Сгенерирован 2026-06-18 агентом по запросу. Ссылки на `chat_index.html` могут
сдвинуться после правок — перед фиксом перепроверять контекст grep'ом.

## 1. IDB priv vs pub рассинхрон

- **:1423-1438** — `saveKeysToIDB` пишет `priv` и `pub` в РАЗНЫХ awaited put'ах одной tx. Если вкладку закроют между ними — priv без pub.
- **:1433** — если `myPub` пуст в момент save, pub не пишется; следующий `loadKeysFromIDB` (1446) вернёт false → priv считается потерянным.

## 2. wipeKeysIDB не трогает peerkeys

- **:1462-1469** — чистит только store `'keys'`. `peerkeys` (TOFU pins) остаются.
- **:2850-2857** — `wipePeerKeysIDB` определена, НИГДЕ не вызывается.
- **:1991-1996** — `rotateMyKey` явно решает не чистить peerkeys (комментарий).
  `pubCache.clear()` есть только тут — везде ещё стейл.

## 3. Multi-device / users.x25519_pub перезаписывается

- **:1682-1685** `_ensureKeysLocal` (d): новый юзер на втором устройстве при `has_pub=false` сгенерит свою пару и зальёт `x25519_pub` через `/keys/upload` → перезапишет ключ первого устройства.
- **:1636, 1648, 2457, 2707** — `/keys/upload` шлёт `x25519_pub: myPub` на каждом логине/импорте/QR-receive. Стейл myPub перезапишет серверный pub.
- **:1199-1200, 1311-1325** — глобальные `myPriv`/`myPub` единственная пара на сессию; `user_devices.pub_key[]` не используется при send.

## 4. Смена пароля → encrypted_private_key зануляется

- **:1553-1554** — после смены пароля `_ensureKeysServer` сгенерит новую пару, перезапишет `x25519_pub`. Устройство Б, оффлайн, со старым priv в IDB — старые сообщения потеряны навсегда.
- **:1611-1615** `_checkLocalPubMatchesServer` — wipe-ает priv БЕЗ подтверждения, тихо. На multi-device приводит к потере локального priv.

## 5. _ensureKeysServer wrong password

- **:1556-1573** — при decrypt fail БРОСАЕТ ошибку, `myPriv`/`myPub` не зануляются явно (могут быть уже занулены через wipe выше).
- **:3082-3094** — при exception из `ensureKeys` token уже в localStorage; `showAuth` не делает `wipeKeysIDB`/`removeItem('gs_token')`. На refresh init вытащит токен → ensureKeys без пароля.

## 6. pubCache стейл

- **:1201, 1318, 1360, 1410, 4318, 6355** — `pubCache` инвалидируется ТОЛЬКО в `rotateMyKey` (1996). При смене ключа собеседника стейл cache блокирует TOFU.

## 7. TOFU rejection — silent partial-send

- **:1316-1317, 1358-1359, 6350-6351** — при отказе `verifyAndPinPub` бросает «Отправка отменена», но в групповом send try/catch ниже глотает → console.warn, для этого участника не шифруется, остальные получают.
- **:1402-1407** `decryptFromPeer` при отказе TOFU кидает, `ingestIncoming` (3586-3588) ставит `[не удалось расшифровать]`, но **ack всё равно отправляется** (5973). Сообщение теряется навсегда.

## 8. Переключение режима server→local

- **:2257** — `mode:'local'` шлётся ДО проверки что приватник реально на устройстве. На ДРУГИХ устройствах priv больше не подтянется, в `_ensureKeysServer` (1554) пойдут в ветку «генерируем заново» → перезапишет pub, сломает связь.
- **:2259-2268** — обратное `local→server` НЕ перешифровывает priv (myPriv non-extractable). При логине → ветка генерации новой пары → потеря всего.

## 9. Race: WS chat.new до ensureKeys

- **:5830-5833, 3514-3590** — `ws.onmessage` не ждёт `myPriv`. Если WS реконнектится в момент когда `_ensureKeysServer` ещё крутит PBKDF2 — `decryptFromPeer` (1394) бросит, `ingestIncoming` сохранит `[не удалось расшифровать]` и **ack уйдёт** → сервер удалит pending, второго шанса нет.
- **:3444-3449** `fetchPending`: `Promise.all` всех pending. Если priv не успел — все ack-ются как successful.

## 10. Группы — `m.x25519_pub` из снимка info

- **:6321-6325, 1204** — `encryptForGroup` использует `activeGroup.members[].x25519_pub` (снимок с момента `openGroupChat` 6391). При смене ключа участника между open и send — устаревший pub.
- **:6608-6611** — receiver берёт `m.envelope_keys[String(me.id)]`. Если у юзера сменился id или пакет был зашифрован под старый pub — `[не удалось расшифровать]`, сохраняется в IDB как тело.

## 11. Восстановление из бэкапа БД

- **:1554, 1611** — клиент сверяет ТОЛЬКО `remote.x25519_pub !== myPub`. Если сервер откатили и pub стал тем же, но encrypted_private_key/salt вернулись СТАРЫЕ, а клиент уже сгенерил новый локально — pub совпадёт, но priv в IDB будет от другого pub.

## 12. Прочие

- **:2452-2457** `openKeyFileImport` — после import всегда шлёт `'local'`, даже если был в `server`.
- **:2792** `onversionchange` тихо закрывает IDB, обнуляет `_idb`. Если идёт `saveKeysToIDB` — tx упадёт, priv в полусохранённом виде.
- **:3246-3247** `doLogout` чистит `keys`, но IDB остаётся открытым. `_idb` указывает на старый — `loadKeysFromIDB` после re-login читает БД ПРЕДЫДУЩЕГО юзера до перезагрузки.
- **:1530** — если save `storage_mode` упал, выбор потерян, при reload снова покажет модалку → другой режим → рассогласование.
